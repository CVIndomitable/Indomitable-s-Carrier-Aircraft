# 修复：长机视角切换时玩家传送问题

## 问题描述

玩家从长机视角切回自身视角时，有时会被传送到飞机所在位置。

## 根本原因

Minecraft 的 `setCamera()` 机制在切换视角时可能导致玩家位置数据同步异常：

1. 进入长机视角时，玩家实体位置保持不变，但摄像机跟随飞机移动
2. 退出视角时直接 `setCamera(player)`，但玩家位置可能已被污染
3. 客户端与服务端位置同步出现竞态条件，导致玩家被拉到飞机位置

## 解决方案

### 实现机制

引入 `CameraStateTracker` 单例，负责：

1. **进入长机视角时**：存储玩家当前位置、俯仰角、偏航角
2. **退出长机视角时**：**先**强制传送玩家回原位置并恢复朝向，**再**切换摄像机
3. **玩家下线时**：清理跟踪状态，防止内存泄漏

### 核心代码

```java
// CameraStateTracker.java
public void enterLeaderCamera(ServerPlayer player) {
    trackedPlayers.put(player.getUUID(), new CameraState(
        player.position(),
        player.getXRot(),
        player.getYRot()
    ));
}

public void exitLeaderCamera(ServerPlayer player) {
    CameraState state = trackedPlayers.remove(player.getUUID());
    if (state != null) {
        player.teleportTo(state.position.x, state.position.y, state.position.z);
        player.setXRot(state.xRot);
        player.setYRot(state.yRot);
    }
}
```

**关键修复点**（2026-07-10 第二次修复）：

`CommandPayload.exitLeaderCamera()` 中的调用顺序**至关重要**：

```java
// ✅ 正确顺序：先传送，再切换摄像机
CameraStateTracker.getInstance().exitLeaderCamera(player);  // 1. 传送玩家到原位置
player.setCamera(player);                                    // 2. 切换摄像机到玩家

// ❌ 错误顺序：先切换摄像机，再传送
player.setCamera(player);                                    // 导致客户端在飞机位置看到玩家
CameraStateTracker.getInstance().exitLeaderCamera(player);  // 传送时机已晚
```

**原因**：`setCamera(player)` 会立即触发客户端摄像机切换到玩家当前位置。如果此时玩家实体位置由于网络同步问题已接近飞机位置，客户端会先看到自己在飞机处，即使之后执行传送也会造成视觉闪烁。先传送再切换摄像机可确保摄像机切换时玩家已在正确位置。

### 变更文件

- **新增**：`CameraStateTracker.java` — 摄像机状态管理器
- **修改**：`CommandPayload.java` — 视角切换命令中调用状态跟踪
- **修改**：`ServerGameEvents.java` — 玩家下线时清理摄像机状态

## 测试验证

### 测试场景

1. **基础场景**：进入长机视角 → 飞机飞远 → 退出视角，玩家应回到原地
2. **快速切换**：连续多次进出长机视角，不应出现位置跳变
3. **飞机移除**：长机被击毁/回收后切回视角，玩家应保持在原位
4. **跨维度**：（如未来支持）长机飞入传送门时的边界情况

### 预期结果

- 玩家始终停留在进入视角前的位置
- 朝向恢复到进入视角前的状态
- 不再出现传送到飞机位置的问题

## 技术注意事项

### 为什么使用 teleportTo 而非直接设置坐标

- `player.setPos()` 仅更新服务端状态，客户端可能延迟同步
- `player.teleportTo()` 会立即发送位置同步包，强制客户端刷新
- 结合 `setXRot/setYRot` 恢复视角朝向，确保体验连贯

### 内存管理

- 使用 `HashMap<UUID, CameraState>` 轻量级存储
- 玩家下线时及时清理（`ServerGameEvents.onPlayerLoggedOut`）
- 每个玩家只保存一条状态（进入时覆盖旧状态）

## 后续优化空间

1. **安全性检查**：退出视角前验证原位置是否安全（无方块碰撞/不在虚空）
2. **多长机支持**：未来如支持切换不同长机，需扩展为栈式状态管理
3. **客户端预测**：可在客户端缓存原位置，减少网络延迟感知
