## 记录格式

每条记录包含：
- **日期**: 变更决定日期
- **类型**: 架构/技术/功能/优化/简化
- **决策者**: AI/用户/协商
- **变更内容**: 简要描述
- **原因**: 为什么做这个变更
- **影响**: 对项目的影响范围
- **状态**: 待实施/已实施/已验证

### 2026-08-16 - P1 重要问题修复（代码审查报告）

- **类型**: 架构/性能
- **决策者**: AI（按代码审查报告 P1 修复路线）
- **变更内容**:
  - **S2 FireControlSystem settings 重载语义不一致修复**: 删除 `settings(UUID)` 与 `getAssignedTarget(UUID, UUID)` 两个无 `ServerLevel` 参数的重载。统一保留 `settings(ServerLevel, UUID)`，从 `CarrierAircraftSavedData.loadSettings` 加载玩家自定义设置，避免出现"服务端用真实设置、客户端用默认值"的不一致。`AircraftEntity.calculateReleaseCount` 删掉客户端分支三元式，只走服务端路径（该方法本就只在 `tickDropping`/`tickDebug` 等服务端 tick 调用）。所有调用方已核对，无需调整
  - **S7 BombEntity 字符串 weaponType 硬编码修复**: 在 `BombEntity` 内新增 `WeaponType` 枚举（`AERIAL_BOMB`/`GUIDED_BOMB`/`AERIAL_TORPEDO`/`ROCKET`），新增 `derive(AmmoType, Collection<SeaAttackMode>)` 推导方法与 `fromLegacyString(String)` 兼容旧 NBT 的兜底映射。构造函数、`getWeaponType`/`setWeaponType`、`applyPhysics` switch 分支全部改为枚举。底层 `DATA_WEAPON_TYPE` 仍以 String 同步数据 + NBT 序列化（保证存档前后兼容），仅 API 暴露枚举。`AircraftEntity.spawnSeaWeapon` 改用 `WeaponType.derive(...)` 推导，避免再次出现字符串拼写
  - **S4 ControlTerminalScreen.renderTerrain 性能热点修复**: 引入 `int[] cachedTerrainGrid` 像素网格缓存，新增 `ensureTerrainGrid` / `needsTerrainRebuild` / `rebuildTerrainGrid` 三个私有方法。地形重建条件为：① 玩家位置变化超过 4 格；② 缩放变化超过 15%；③ 客户端 tick 超过 20 间隔（兜底）。正常情况下每帧只做 `g.fill` 绘制，把每帧 ~1100 次同步世界查询降到初次/移动时一次，最坏每 20 tick 一次
- **原因**: `docs/代码审查报告_2026-08-16.md` 列出的 3 个 P1 重要问题——settings 重载语义不一致、字符串 weaponType 拼写不可编译期检查、地形渲染主线程同步查询累积卡顿
- **影响**:
  - `FireControlSystem` API 收紧，删除两个旧重载（无外部调用方）
  - `BombEntity` import 列表调整（新增 `AmmoType`/`SeaAttackMode`/`java.util.Collection`，移除 `EnumSet`）
  - `AircraftEntity.spawnSeaWeapon` 不再依赖 `SeaAttackMode.DIVE_BOMBING` 字符串判断，统一从 `WeaponType.derive` 推导
  - `ControlTerminalScreen` 新增 ~50 行缓存相关字段与方法
- **状态**: 已实施，`./gradlew compileJava` 已验证

### 2026-08-16 - P0 严重问题修复（代码审查报告）

- **类型**: 架构/安全
- **决策者**: AI（按代码审查报告 P0 修复路线）
- **变更内容**:
  - **S1 BombEntity 爆炸双重伤害修复**: 重构 `explode()` 方法，把距离衰减公式封装到自定义 `BombExplosionDamageCalculator`（继承 `ExplosionDamageCalculator`），删除主循环中的手动 `target.hurt()`。新计算器通过 `shouldDamageEntity` 控制敌我识别、`getEntityDamageAmount` 应用距离衰减。占位的 `BlockOnlyExplosionDamageCalculator` 负责方块破坏+视效+击退。`level.explode()` 一次调用完成所有逻辑，避免实体被多处伤害通道重复击中
  - **S3 静态单例跨存档泄漏修复**: 在 `ServerGameEvents` 新增 `onServerStarted` 处理函数，与原有 `onServerStopped` 调用同一 `clearAllSingletons` 兜底清理流程（双保险，覆盖单机模式世界切换的边界情况）。补充 `CameraStateTracker.clearAll()` 与 `HitNotifier.clearAll()` 方法，确保火控系统/编组管理器/相机追踪/通知偏好四个静态单例在新存档启动与服务器停止时全部归零
  - **S5 反潜 GLOWING 残留修复**: `tickAswDetection` 在 `removeIf` 阶段对离开 AABB 的 UUID 主动调 `removeEffect(GLOWING)`；`clearAswGlow()` 在 `remove()` 或转 RETURNING 时也对 `glowingTargets` 集合内所有实体调 `removeEffect(GLOWING)`。保证反潜机被召回/销毁/移出探测范围后，目标 GLOWING 不会残留 80 tick
- **原因**: `docs/代码审查报告_2026-08-16.md` 列出的 3 个 P0 严重问题——双重实体伤害、单机跨存档残留、反潜 GLOWING 残留。修复后爆炸逻辑单点收敛、单例状态可重入、反潜效果有始有终
- **影响**:
  - `BombEntity` import 列表调整（移除 `Optional`/`SimpleExplosionDamageCalculator`，新增 `Explosion`/`DamageSource`/`HashMap`/`HashSet`）
  - `CameraStateTracker` / `HitNotifier` 新增 `clearAll()` 公共方法
  - `ServerGameEvents` 新增 `ServerStartedEvent` 订阅
- **状态**: 已实施，`./gradlew compileJava` 已验证

### 2026-07-02 - 机型配置改为 JSON 数据包

- **类型**: 架构/技术
- **决策者**: 用户
- **变更内容**: 将机型配置从硬编码改为 JSON 数据包驱动：
  - 新增 `AircraftSpecLoader` 数据加载器，使用 NeoForge 的 `SimpleJsonResourceReloadListener`
  - 数据包路径：`data/<namespace>/aircraft/<aircraft_id>.json`
  - 内置 4 个默认机型（b25、btd、rocket_attacker、asw_patrol）作为 fallback
  - 修改 `AircraftSpawnerItem` 和 `AircraftEntity` 使用加载器而非硬编码常量
  - 支持 `/reload` 热重载
- **原因**: 
  - 原始设计要求"所有机型参数数据驱动（JSON 数据包），新增机型不改代码"
  - 硬编码妨碍数据包作者添加自定义机型和调整平衡性
- **影响**: 
  - `AircraftSpec.B25/BTD/ROCKET_ATTACKER/ASW_PATROL` 常量保留但不再直接使用
  - 新增 `AircraftSpecLoader` 类和 4 个 JSON 配置文件
  - `CommonModEvents` 注册数据加载监听器
  - 数据包作者可以覆盖内置机型或添加新机型
- **状态**: 已实施，编译验证通过

### 2026-06-10 - 代码审查后的高中优先级修复

- **类型**: 功能/优化/简化
- **决策者**: AI（工程默认值待策划确认，见 [待策划细化清单](待策划细化清单.md)）
- **变更内容**:
  - **敌我识别**: 目标筛选从"任意活物"收紧为 `Enemy` 接口的敌对生物，并显式排除己方飞机（修复自卫模式下友机互射、自动锁定轰炸牛/村民）
  - **飞行物理**: `flyTowards` 不再手动 `move()`，位移统一由原版 `FlyingMob#travel` 应用（修复每 tick 双重移动导致实际速度约为设定值 2 倍）
  - **弹道解算**: 下落时间改为按 `BombEntity` 实际物理（0.98 阻力 + 0.05 重力）逐 tick 模拟；投弹释放距离由机速漂移积分计算并作为投弹触发条件；`attackHeight` 语义从绝对 Y 改为相对目标的高度差（默认值 B25 36 / BTD 20 / 火箭 16 / 反潜 24，待调参）
  - **爆炸**: 取消双重伤害（原版爆炸只破坏方块+击退，实体伤害仅由衰减公式结算）；地形破坏从 TNT 模式改为 MOB 模式（受 `mobGriefing` 游戏规则约束）；炸弹不再与己方飞机碰撞引爆
  - **弹药经济**: 返航补给从凭空回满改为消耗主人背包中的航空弹药物品（1 件 = rounds() 发），创造模式免费
  - **坐标目标过期**: 火控坐标目标 5 分钟后自动失效（修复无限轰炸循环）；火控目标记录所属维度，跨维度失效
  - **下线保护**: 主人离线时飞机原地盘旋等待而非被删除；新增 `removeWhenFarAway=false` 防自然消失
  - **生命周期清理**: 玩家登出/服务器停止时清理火控系统与编组管理器的静态单例数据（修复内存泄漏与单机跨存档残留）
  - **死代码清理**: 删除未被引用的 `combat/` 包（BallisticSolver、HitNotifier）、死状态 `CIRCLING`、悬空注册的 4 个 DataComponent、`BombEntity` 中遮蔽父类的 `tickCount` 字段
- **原因**: 全面代码审查发现的高/中优先级问题，详见审查结论
- **影响**: 玩法表现（速度、投弹精度、目标选择）与修复前明显不同，需要重新进行游戏内测试
- **状态**: 已实施，`./gradlew compileJava` 已验证
